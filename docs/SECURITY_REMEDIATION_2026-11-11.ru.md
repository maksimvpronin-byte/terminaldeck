## Исходные 25 замечаний

- **GHSA-g3hv-75wg-m249 / CVE-2026-118764:** minimatch 9.0.9 и 10.2.6 заменены на 11.0.8 через override диапазона `>=7.0.0 <11.0.1`. Старые ветви 3.x/5.x сохранены. Проверены вызовы CommonJS из app-builder-lib, @electron/universal и typescript-estree, шаблоны файлов и ESM-импорт @electron/universal.
- **24 CVE старых 7-Zip:** из разрешаемого дерева удалены electron-builder-squirrel-windows, electron-winstaller и их ненужные зависимости. `.npmrc` использует `legacy-peer-deps=true`: прежний `omit=peer` исключал установку, но сохранял эти пакеты в lock-файле, по которому работал исходный сканер. Нужные peer-зависимости объявляются явно; автоматическая проверка совместимости peers npm в этом режиме отключена.
- Lock-файл содержит 570 пакетов вместо 585. В чистой Windows-установке присутствуют 520 пакетов; различие включает платформенные optional-зависимости. Обе исключённые npm-зависимости и уязвимые версии minimatch отсутствуют как в lock-файле, так и в установленном дереве.

## Предотвращение повторения

Команда `npm run verify:security` проверяет lock-файл и фактическую установку. Регрессионные проверки охватывают старую peer-зависимость, оставшуюся только в lock-файле, лишнюю установленную уязвимую зависимость, а также старый minimatch и архиватор внутри ASAR.

CI и релизная сборка выполняют эту команду и сетевой npm audit, включая инструменты сборки. Платформенные проверки выполняют проверку компонентов на Windows/macOS. Режим `verify-release --package` дополнительно инспектирует ресурсы и ASAR собранного приложения. Это адресная проверка известных компонентов; она не заменяет сканер CVE для всех нативных библиотек.

## Исправление нативных библиотек

Grype 0.121.3 установлен из официального релиза с проверкой SHA-256; база от 11.11.2026. Первый скан готового Windows-приложения уже не содержал ни одного из 25 идентификаторов исходного HTML, но обнаружил дополнительные проблемы:

- FreeRDP 3.31.0: **100 уникальных CVE**, 400 совпадений по четырём DLL. Это сопоставления CPE по версии; применимость каждого совпадения к используемым компонентам требует отдельного анализа. В том числе есть подтверждённый upstream advisory [GHSA-6wqx-rv3q-vcxp](https://github.com/FreeRDP/FreeRDP/security/advisories/GHSA-6wqx-rv3q-vcxp), исправленный в 3.32.2.
- zlib 1.3.2 в `resources/freerdp/bin/z.dll`: **CVE-2026-85091**. [zlib 1.4](https://zlib.net/) содержит исправление. При переходе на 1.4 на Windows нужно пересобрать зависимые библиотеки: изменились имена библиотек и некоторые ABI-настройки.

После расширения задачи нативные библиотеки обновлены и пересобраны:

| Компонент | До | После |
| --- | --- | --- |
| FreeRDP / WinPR | 3.31.0 | 3.33.1 |
| zlib | 1.3.2 | 1.4 |
| Grype, Windows-приложение | 401 совпадение, 101 уникальный CVE | **0 совпадений** |

- Версии закреплены в `resources/freerdp/native-versions.json`. FreeRDP 3.33.1 взят из официального тега; сохранена локальная правка совместного чтения файлов буфера обмена.
- Для Windows добавлен overlay-порт zlib 1.4 из официального release-архива с закреплённым SHA-512. SHA-256 скачанного архива совпал с digest официального GitHub Release. При восстановлении старого vcpkg-кэша скрипт обновляет именно zlib, затем пересобирает зависимый клиент.
- macOS явно использует zlib из Homebrew и требует версию не ниже 1.4. Добавлены аргументы CMake, исключающие случайный выбор старой системной zlib.
- Упаковщики проверяют маркер собранных версий; отсутствующий или устаревший кэш пересобирается. Маркер включается в приложение; `verify-release --package` отклоняет отсутствующие и устаревшие сведения о нативных версиях. Ключи CI-кэшей учитывают версии и overlay-порт.
- Нативные CTest: **3 из 3 прошли** — видимость кадров, текстовый буфер обмена, альфа-канал указателя. Пересобранный `td-rdp.exe` загрузил DLL, создал контекст клиента и вернул ожидаемую протокольную ошибку на пустой ввод; сетевого подключения при проверке не было.
- Целевые тесты RDP: **6 файлов, 91 тест прошёл**. Новые проверки безопасности: **4 теста прошли**. Синтаксис PowerShell и macOS Bash-скриптов проверен.
- Заново собраны Windows NSIS и portable в `output/security-remediation/packages-native/`. Итоговый скан распакованного приложения, включая его нативные DLL: `grype-windows-after.json`, **0 находок**, без правил подавления CVE. Отдельный скан нативного каталога: `grype-native-after.json`, также **0**.

Полезные файлы проверки: `native-build.log`, `native-shim.log`, `native-bundle.log`, `grype-native-after.json`, `grype-windows-after.json` и `packages-native/` в `output/security-remediation/`. Предыдущие `packages/` и `grype-windows.json` сохраняют состояние до обновления нативных библиотек.
