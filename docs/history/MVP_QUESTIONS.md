# TerminalDeck — вопросы по MVP

Аналог MobaXterm / Royal TSX. Начинаем с MVP на SSH, сборка под macOS и Windows (Linux — следующим шагом).
Отвечай прямо под вопросами (можно кратко, можно "как рекомендуешь").

---

## 1. Технологический стек

Кроссплатформенность (Mac + Windows + позже Linux) сильно сужает выбор. Варианты:

- **Electron + TypeScript/React + xterm.js + ssh2 (node)** — (рекомендую для MVP)
  Плюсы: быстрее всего пишется, огромная экосистема, xterm.js — тот же терминал, что в VS Code, ssh2 — зрелая SSH-библиотека на JS. Минусы: больше вес дистрибутива (~150-200MB), выше потребление памяти.
- **Tauri (Rust backend) + React/Svelte frontend + xterm.js + russh/ssh2-crate**
  Плюсы: лёгкий (~10-20MB), быстрее и безопаснее по памяти. Минусы: SSH/PTY экосистема на Rust менее зрелая, дольше писать MVP, сложнее находить готовые решения "из коробки".
- **Нативно (Swift на Mac + C#/WinUI на Windows)**
  Плюсы: максимальная нативность и производительность. Минусы: два разных кодбейза с нуля — для MVP overkill, Linux потом = третий кодбейз.

**Вопрос:** Electron для скорости MVP, или сразу Tauri ради лёгкости/производительности (дольше стартовая разработка)?

## 2. Объём функционала MVP (что входит в "SSH MVP")

Обязательное ядро которое вижу в любом случае:
- Менеджер сохранённых подключений (host/port/user)
- Дерево/список сессий в сайдбаре (как в MobaXterm)
- Подключение по SSH, полноценный терминал с вкладками
- Аутентификация: пароль + SSH-ключ (файл)

Вопрос — что из следующего включаем **в MVP**, а что откладываем на потом:
- [ ] SSH-агент (agent forwarding, интеграция с ssh-agent/Pageant)
- [ ] Jump host / ProxyJump (подключение через промежуточный сервер)
- [ ] SFTP-браузер файлов рядом с терминалом (как в MobaXterm split-view)
- [ ] Split panes / несколько терминалов в одном окне
- [ ] Хранение группы серверов (папки/теги)
- [ ] Port forwarding (local/remote/dynamic — SOCKS)
- [ ] Логирование сессии в файл
- [ ] Импорт существующих подключений (PuTTY sessions, известные хосты и т.п.)

## 3. Хранение credentials

- Где хранить пароли/пассфразы от ключей: **системный keychain** (macOS Keychain / Windows Credential Manager) — рекомендую, безопаснее и без своего мастер-пароля для MVP.
- Либо: собственное зашифрованное хранилище с единым мастер-паролем (как KeePass) — больше контроля, чуть больше работы для MVP.

**Вопрос:** системный keychain, или свой encrypted vault с мастер-паролем?
