# План: первое знакомство с TerminalDeck

Статус: предложение для будущей реализации. Код приложения не изменён.
Основание: обзор версии 0.11.1 от 5 сентября 2026 года.

## 1. Цель и границы

Помочь новому пользователю открыть первое подключение и понять, где сохраняются
хосты и как организовать дальнейшую работу. Опытный пользователь должен сразу
перейти к своим задачам.

Первый выпуск включает стартовый экран, доступ к существующим диалогам,
краткий справочник понятий и небольшой набор контекстных подсказок.
Полный интерактивный тур с затемнением экрана, демонстрационный сервер,
обучение всем протоколам и переделка диалогов подключения остаются за рамками.
Обучение не требует успешного подключения для завершения или пропуска.

## 2. Что уже есть

- `App.tsx`: создание мастер-пароля, разблокировка и защита рабочего интерфейса.
- `Workspace.tsx`: пустое рабочее пространство с коротким текстом без кнопок действий.
- `Sidebar.tsx`: открытие диалогов новой сессии, быстрого SSH-подключения,
  импорта SSH config, настроек и других сценариев.
- `HelpDialog.tsx`: справка о возможностях и сочетаниях клавиш.
- `MainLayout.tsx`: общая композиция интерфейса и первоначальная загрузка данных.
- `state/settings.ts`, `state/slices/settings.ts`: локальные настройки.
- `i18n`: английский и русский языки; сочетания клавиш форматирует `keyHint`.

Переиспользовать существующие операции и проверки подключения. Новая кнопка
должна открывать тот же диалог, что и соответствующая команда боковой панели.

## 3. Первый запуск

### 3.1. Создание хранилища

Сохранить существующий обязательный шаг создания мастер-пароля. Уточнить текст:
пароль защищает сохранённые учётные данные локально; это не пароль от сервера.
Не обещать восстановление забытого мастер-пароля.

Стартовый экран показывать после разблокировки и успешной загрузки локальных
данных. Пока данные загружаются, не принимать пустые массивы за новый профиль.
При ошибке загрузки показать ошибку и повтор, а не приглашение создать всё заново.

### 3.2. Экран «Начните работу с TerminalDeck»

Разместить экран в свободной центральной области, сохранив видимой боковую панель.
Одна основная кнопка и два вторичных действия:

| Действие | Пояснение | Результат |
| --- | --- | --- |
| Добавить подключение | Сохраните SSH- или RDP-хост для следующего раза | Существующий диалог новой сессии |
| Быстро подключиться по SSH | Откройте разовое подключение | Существующий QuickConnectDialog |
| Импортировать SSH config | Выберите подключения из локального файла | Существующий ImportSshConfigDialog |

Под ними — ссылки «У меня есть резервная копия», «Хосты хранятся в Git / Ansible»
и «Как устроено приложение». Первая открывает вкладку резервных копий настроек;
вторая — справочный раздел с переходом к добавлению источника инвентаря.
Не запускать чтение репозитория или импорт от одного открытия стартового экрана.

Внизу: «Пропустить знакомство» и пояснение «Его можно открыть снова в справке».
После пропуска оставить обычное компактное пустое состояние с полезными кнопками.

Отмена любого диалога возвращает к стартовому экрану без потери его состояния.
Сохранение хоста не означает, что соединение установлено: после сохранения
подсказать «Откройте хост двойным щелчком в списке слева».

### 3.3. Первое подключение

После реального перехода SSH- или RDP-соединения в состояние connected показать
небольшую закрываемую подсказку «Подключение открыто». Она не получает фокус
и не перекрывает терминал или удалённый рабочий стол.

При ошибке соединения обучение не продвигается автоматически. Существующее
сообщение об ошибке остаётся основным; обучение не показывает второй диалог.
Пользователь может исправить настройки, выбрать другой путь или закончить знакомство.

Проверка ключа SSH и сертификата RDP остаётся обычной частью подключения.
Обучение не принимает доверие за пользователя и не советует безусловно подтверждать его.

## 4. Объяснение организации хостов

Добавить в справку раздел «Как устроено приложение» с короткой схемой
«Сохранённые хосты / Инвентарь → открытые подключения в рабочем пространстве».
Коллекции показать как ещё один способ собрать и открыть нужные хосты.
Схема статическая, с текстовым эквивалентом для экранного диктора.

| Понятие | Объяснение пользователю |
| --- | --- |
| Сохранённый хост | Адрес и настройки подключения, доступные при следующем запуске |
| Группа / папка | Место для хостов с общими настройками, например логином |
| Инвентарь | Хосты из Ansible-репозитория с локальными переопределениями |
| Папка с Git | Хосты из репозитория внутри обычного дерева сессий |
| Коллекция | Сохранённый набор хостов для совместного открытия; хост может быть в нескольких наборах |
| Рабочее пространство | Контейнер открытых вкладок; закрытие завершает подключения в нём |

Сначала показать только хост, группу и рабочее пространство. Инвентарь,
Git-папки и коллекции раскрывать в подразделе «Когда хостов станет больше».
Пример: группа «Production» задаёт общий логин, коллекция «Дежурство» собирает
нужные хосты из разных групп, рабочее пространство содержит открытые подключения.
Примеры являются иллюстрациями и не создают реальные записи или команды.

## 5. Контекстные подсказки

Добавлять после выпуска стартового экрана. Показывать максимум одну одновременно,
по одному разу для каждого события, с кнопкой закрытия и общим отключением.

| Контекст | Содержание |
| --- | --- |
| Первый сохранённый хост | Двойной щелчок подключает; контекстное меню открывает настройки |
| Первое успешное SSH-подключение | Где открыть SFTP и как найти хост через палитру |
| Первое успешное RDP-подключение | Где полноэкранный режим и как из него выйти |

Точное место привязки проверить в работающем интерфейсе перед реализацией.
Подсказку про RDP показывать в оконном режиме до входа в полный экран.
В полном экране не рисовать обучающих элементов поверх удалённого рабочего стола.
В первой версии не обучать broadcast, массовому выполнению команд и удалению.

Если открыты модальные окна, запрос авторизации, проверка доверия или блокировка,
отложить показ. После закрытия повторно проверить актуальность события: подсказка
для уже закрытого подключения не появляется. Не забирать фокус у терминала.

## 6. Существующие пользователи и повторный запуск

- Отсутствие записи об обучении после обновления не означает новый профиль.
- Существующий vault без записи об обучении считать существующим профилем;
  знакомство доступно из справки, автоматически не открывается.
- Новый профиль определяется по созданию vault в этом запуске. Если до окончания
  начальной загрузки появились импортированные данные, открыть обычный интерфейс.
- Повторное открытие: «Справка → Знакомство с приложением».
- При активных подключениях повторное знакомство открывается как справочный диалог,
  не заменяет рабочую область и не размонтирует терминалы.
- Отдельная команда «Показывать подсказки снова» сбрасывает только отметки подсказок.
- Обновление версии приложения не сбрасывает пропуск и завершение знакомства.

## 7. Техническая реализация

### Общие действия интерфейса

Сейчас флаги открытия диалогов находятся в `Sidebar.tsx`. Вынести координацию
нужных диалогов в общий слой под `MainLayout` (например, `useConnectionActions`
и `ConnectionDialogs`). Передавать действия в Sidebar и стартовый экран.
Сохранить контекст создания сессии внутри конкретной группы.
Не дублировать формы, не открывать их искусственными кликами по DOM.

### Компоненты

- `GettingStarted.tsx`: центральный стартовый экран.
- `GettingStartedGuide.tsx`: повторно открываемое руководство и объяснение понятий.
- `OnboardingHint.tsx`: необязательная контекстная подсказка.
- `state/onboarding.ts`: загрузка, проверка структуры, миграция и правила показа.
- Подключение к `App`, `MainLayout`, `Workspace`, `Sidebar`, `HelpDialog`, i18n и стилям.

Названия предложены для планирования; уточнить при реализации без изменения сценариев.

### Локальное состояние

Хранить отдельно от учётных данных и списка подключений, по текущему подходу
локальных настроек renderer. Предлагаемая структура:

```ts
interface OnboardingState {
  schemaVersion: 1
  status: 'pending' | 'completed' | 'dismissed' | 'existing-user'
  hintsEnabled: boolean
  seenHints: string[]
}
```

Проверять структуру при чтении. При повреждении состояния или недоступности
хранилища приложение продолжает работу; автоматически навязанный тур не появляется.
Изменения в этом случае действуют в памяти до закрытия приложения.

`pending` выставляется после создания нового vault; `completed` — после первого
реально успешного подключения или явного «Закончить знакомство»;
`dismissed` — после пропуска. Открытие формы и сохранение хоста не завершают обучение.
Повторное открытие руководства не меняет статус и не сбрасывает seenHints.
Хранить только прогресс: без адресов, логинов, паролей и содержимого терминала.
Не включать этот прогресс в переносимую резервную копию подключений.

### Доступность и локализация

- Все строки через существующую i18n; русский и английский входят в первый выпуск.
- Сочетания клавиш через `keyHint`, с учётом платформы.
- Понятный порядок Tab, видимый фокус, семантические кнопки и заголовки.
- Для руководства в диалоге: удержание фокуса, Escape и возврат фокуса инициатору.
- Подсказки не перехватывают клавиатуру; действия доступны без мыши.
- Проверить светлую и тёмную темы, минимальное окно 900 × 560 и длинные русские строки.
- Новые элементы остаются внутри защищённой области интерфейса при блокировке vault.

## 8. Этапы и критерии готовности

### Этап 1. Стартовый экран — самостоятельный первый выпуск

- [ ] Общие действия и диалоги доступны из Sidebar и GettingStarted.
- [ ] Новый профиль получает стартовый экран после загрузки данных.
- [ ] Работают создание сессии, быстрое SSH-подключение, импорт SSH config и переход к восстановлению.
- [ ] Пропуск сохраняется между запусками; существующие профили не получают автоматического обучения.
- [ ] Пустое рабочее пространство содержит доступные действия после пропуска.
- [ ] Есть минимальная справка с повторным открытием знакомства и объяснением Git-пути.
- [ ] RU/EN, клавиатура и блокировка vault проверены.

### Этап 2. Объяснение организации

- [ ] Справочник и схема объясняют шесть понятий на одном примере.
- [ ] Расширенные понятия доступны по запросу.
- [ ] Повторный просмотр при открытых подключениях сохраняет сессии и введённые данные.

### Этап 3. Подсказки по месту

- [ ] Три контекстные подсказки привязаны к реальным событиям.
- [ ] Есть закрытие, общее отключение и отдельный сброс отметок.
- [ ] Нет конфликтов с фокусом терминала, диалогами, блокировкой и полным экраном.

Каждый этап можно выпустить отдельно. Расширение числа подсказок — после проверки
с пользователями; обязательного многошагового мастера в этих этапах нет.

## 9. Проверка реализации

Автоматические проверки должны проверять поведение:

- Матрица нового/существующего профиля, статусов, перезапуска и повреждённых настроек.
- Задержанная или неудачная загрузка данных не вызывает ложного первого запуска.
- Кнопки стартового экрана открывают нужный существующий диалог; отмена возвращает назад.
- Сохранение хоста и неудачное соединение не отмечаются как успешное подключение.
- Пропуск и завершение не мешают повторно открыть руководство.
- Блокировка исключает доступ к новым кнопкам и подсказкам.
- Повторное знакомство не размонтирует активные панели подключения.

Ручная проверка на тестовых хостах: первый SSH и RDP, неверный пароль, отмена
проверки доверия, импорт и его отмена, повторный запуск после пропуска,
клавиатурная навигация, минимальное окно, обе темы и оба языка.
Резервную копию восстанавливать только в отдельном тестовом профиле.

Перед выпуском: `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`
и проверка сценариев в упакованном приложении на macOS и Windows.

## 10. Как оценить пользу

Провести короткую проверку с 3–5 людьми, ранее не работавшими с TerminalDeck,
на заранее подготовленных тестовых подключениях. Наблюдать без подсказок ведущего.

Задания: открыть первое подключение; найти способ сохранить ещё один хост;
объяснить разницу между группой и рабочим пространством; пропустить знакомство
и найти его снова. Для этапа 2 добавить объяснение коллекции.

Целевой ориентир: большинство участников открывает первое подключение за
3 минуты после разблокировки при готовых реквизитах и доступном сервере.
Отдельно записывать задержки сети и авторизации. Это цель, а не обещание скорости.
Не добавлять сетевую аналитику ради обучения: для первого выпуска достаточно
наблюдений, времени выполнения заданий и списка затруднений.
